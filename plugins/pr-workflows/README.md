# PR workflows

Seven skills for GitHub and Azure DevOps pull requests. They run in the current
agent's context and do not install hooks, agents, or scheduled jobs.

Use `pr-prepare` to assess or publish changes, `pr-review` for a fresh review,
`pr-validate` to verify behavior, and `pr-status` for a read-only snapshot.
Use `pr-diagnose` for failed checks, `pr-comments` for existing feedback, and
`pr-watch` for ongoing ownership through green CI and valid approval.
Each skill retains its own authorization limits. None authorizes merging.

## Requirements

Use existing authenticated provider tools. The bundled `pr-watch` collector
requires Node 20 or later, GitHub CLI for GitHub, or Azure CLI sign-in
(or an existing `AZURE_DEVOPS_EXT_PAT`) for Azure DevOps.
Keep watcher state in session artifacts, outside the repository.
See its [monitoring contract](skills/pr-watch/references/monitoring.md).

For browser-based validation or other domain work, install the needed supporting
plugin separately, such as `mnmstack` for `browser`. Plugin dependencies are not
installed automatically.
